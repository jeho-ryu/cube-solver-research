# 큐브를 풀 때 신경망에 어떤 일을 맡길 수 있을까?

min2phase는 첫 풀이를 금방 찾아냅니다. 제가 궁금했던 건 그다음이었습니다. 몇 초를 더 쓸 수 있다면, 이미 찾은 풀이를 신경망이 더 짧게 고칠 수 있을까? 첫 실험에서 min2phase가 15수에 푼 큐브를 신경망 솔버인 AlphaCube가 10수에 풀었습니다. 다섯 수가 줄어든 건 분명했지만, 그 큐브를 min2phase에도 조금 더 맡겨 봐야 어느 쪽이 시간을 잘 쓴 건지 알 수 있었습니다.

## 15수짜리 풀이를 10수로 줄인 뒤

AlphaCube에는 두 가지 일을 시켰습니다. 하나는 처음 섞인 상태에서 기존 풀이보다 짧은 해를 다시 찾는 일이었습니다. 첫 풀이가 15수라면 14수까지만 탐색했습니다. 다른 하나는 이미 찾은 풀이에서 긴 구간만 골라 줄이는 일이었습니다. 예를 들어 여덟 번 돌리는 구간을 줄이려면, 완성된 큐브에서 그 여덟 동작을 거꾸로 되짚습니다. 거기서 일곱 수 이내에 다시 완성할 수 있다면 원래 구간을 그 수순으로 바꿀 수 있습니다. 바꾼 풀이를 처음부터 끝까지 별도 큐브 모델에서 돌려 보고 실제로 맞을 때만 채택했습니다.

10회, 20회, 25회씩 섞은 큐브를 합해 30개 준비했습니다. min2phase의 첫 해를 구한 뒤 세 방법에 각각 3초씩 주었습니다. 먼저 탐색을 마치면 바로 끝냈고, 시간은 탐색 단계 사이에 확인했습니다. 표의 회전 수는 한 면을 180도 돌려도 한 수로 세는 HTM 기준입니다.

| 첫 해를 얻은 뒤 한 일 | 평균 회전 수 | 첫 해보다 짧아진 큐브 |
|---|---:|---:|
| 첫 해를 그대로 사용 | 17.900수 | — |
| AlphaCube로 처음부터 다시 풀기 | 16.100수 | 14/30개 |
| AlphaCube로 일부 구간만 교체 | 17.667수 | 2/30개 |
| min2phase가 탐색하던 곳에서 계속 찾기 | 15.167수 | 23/30개 |

AlphaCube로 다시 풀어 얻은 이득은 30개를 합쳐 54수였습니다. 그런데 min2phase가 같은 자리에서 탐색을 이어 가면 82수를 줄였습니다. 두 방식에 준 시간은 같았지만 실제로 쓴 추가 시간은 각각 평균 1.21초와 2.08초였습니다. 15수에서 10수가 된 사례는 신경망을 써 볼 이유가 됐고, 30개를 비교한 결과는 기존 솔버에 시간을 더 주는 방법도 꽤 강하다는 걸 보여 줬습니다. [후처리 실험과 실제 수순](../benchmarks/dnn-postprocess/REPORT.md)

## 다음 회전을 잘 고르면 끝까지 풀 수 있을까?

이번에는 min2phase의 풀이 과정을 학습 예제로 썼습니다. 중간 상태를 하나 보여 주고 그때 min2phase가 선택한 다음 회전을 예측하게 했습니다. 학습에 쓰지 않은 754개 상태에서 기존 AlphaCube가 같은 회전을 고른 비율은 64.59%였고, 추가 학습 후에는 66.31%였습니다. 그런데 새 큐브 60개를 처음부터 풀게 하니 둘 다 57개를 풀었습니다. 같은 구조를 처음부터 학습시킨 모델은 7개를 풀었습니다. 중간에서 한 번 잘 고르는 능력이 늘어도, 여러 번 연속으로 선택해서 큐브를 완성하는 데까지 그 이득이 이어지지는 않았습니다. [추가 학습 실험](../benchmarks/dnn-teacher/REPORT.md)

직접 만든 솔버에서는 유망한 경로를 여러 개 남겨 두는 **빔서치**를 썼습니다. 문제는 어떤 경로를 남기느냐였습니다. 한 수씩 놓고 보면 그럴듯한 선택이어도, 몇 번 돌리고 나면 여전히 완성에서 멀 수 있습니다. 그래서 다음 회전의 점수(Policy)와 함께, 그 회전을 한 뒤 몇 수쯤 더 필요할지(Value)도 예측하게 했습니다. 학습할 때 남은 수는 min2phase 등의 시범 풀이에서 가져왔습니다.

학습 상태를 약 4만 7천 개에서 20만 개로 늘리고, 완성까지 네 수 이내인 상태는 표에서 마무리 수순을 꺼냈습니다. 한 번 막히면 다음 시도에서 회전 후보를 더 넓게 봤습니다. 각 시도는 0.5초를 나눠 썼습니다.

| 같은 큐브 100개를 세 번씩 시도 | 세 번 모두 푼 큐브 |
|---|---:|
| 이전에 만든 솔버 | 26개 |
| 새 솔버에서 Value 점수만 빼고 탐색 | 38개 |
| 새 솔버에서 Value 점수까지 사용 | 47개 |
| min2phase | 100개 |

26개에서 47개로 늘어난 데에는 여러 변경이 함께 들어갔습니다. 그중 남은 수를 예측한 효과가 궁금해서 후보 수, 정답표, 재시도 조건을 그대로 두고 Value 점수만 빼 봤습니다. 그때가 38개였으니, 이 조건에서는 남길 경로를 정할 때 Value를 쓴 쪽이 아홉 개를 더 풀었습니다. 다만 20회 섞은 큐브 25개에서는 새 솔버도 하나도 풀지 못했습니다. 비교용 min2phase에는 0.5초 중단 조건을 걸지 않고 첫 해를 구했습니다. [독립 솔버 실험과 섞기 횟수별 결과](../benchmarks/dnn-standalone/REPORT.md)

## 풀이는 min2phase에 맡기고, 신경망은 순서만 고른다면

신경망에 맡겨 보고 싶었던 일은 하나 더 있었습니다. 기존 솔버가 여러 경로 중 어느 쪽부터 볼지 고르는 일입니다. min2phase는 먼저 조각의 방향과 일부 위치를 맞추고(Phase 1), 거기서 남은 조각을 맞춥니다(Phase 2). 첫 단계를 마친 상태가 여러 개라면 어떤 상태에서는 두 번째 단계가 쉽게 끝납니다. 그런 후보부터 시도할 수 있으면 큐브 전체를 신경망으로 풀 필요가 없겠다고 생각했습니다.

첫 단계를 통과한 후보를 최대 16개 모아, 이미 쓴 수와 모델이 예측한 남은 수의 합이 작은 순서로 시도했습니다. 25회 섞은 큐브 60개를 세 번씩 풀면서 21수 이하 첫 해가 나올 때까지 쟀습니다.

| 후보 처리 방법 | 첫 해까지 걸린 시간의 중앙값 |
|---|---:|
| 원래 min2phase처럼 후보가 나오는 대로 탐색 | 0.5121ms |
| 후보를 모은 뒤 들어온 순서대로 탐색 | 0.7772ms |
| 후보를 모은 뒤 거리표 점수로 정렬 | 0.8536ms |
| 후보를 모은 뒤 신경망 점수로 정렬 | 0.8317ms |

후보를 모으는 것만으로도 시간이 늘었습니다. 모아 둔 후보를 신경망으로 정렬하니 들어온 순서대로 풀 때보다 Phase 2 탐색 호출은 평균 2,653회에서 2,448회로 줄었습니다. 그런데 점수를 계산하고 정렬하는 데만 평균 0.2068ms가 들었습니다. 호출을 덜 하는 효과를 실제 풀이 시간에서는 보기 어려웠습니다. [후보 정렬 실험과 시간 측정](../benchmarks/dnn-ranking/REPORT.md)

첫 해가 늦게 나와도 같은 시간에 더 짧은 풀이를 낸다면 쓸 이유는 남습니다. 그래서 새 큐브 100개를 세 번씩 돌려, 100ms 안에 18수 이하의 해를 낸 횟수를 따로 셌습니다. 기본 방식은 300번 중 94번, DNN 정렬은 70번이었습니다. 프로세스를 켜고 표와 모델을 준비할 때까지 포함해 잰 최대 메모리 사용량의 중앙값도 66.08MiB에서 72.76MiB로 늘었습니다. [고정 시간에서의 해법 길이와 메모리](../benchmarks/dnn-quality/REPORT.md)

## 시작할 때 딱 한 번만 고르게 해 봤습니다

후보를 모을 때마다 모델을 부르는 비용이 컸으니, 마지막에는 큐브 하나당 한 번만 부를 자리를 찾았습니다. min2phase가 사용할 수 있는 시작 방향은 여섯 가지입니다. 거리표로 먼저 점수를 매기고, 최저 점수가 같은 방향이 둘 이상일 때만 작은 신경망이 어느 쪽부터 볼지 고르게 했습니다.

모델의 가중치는 약 4.7KiB였습니다. 구조를 그대로 두고 학습 큐브를 3천 개, 1만 개, 3만 개로 늘렸습니다. 규모마다 초기값을 바꿔 세 번씩 학습한 뒤, 새 큐브 2,000개에서 평균 풀이 시간을 쟀습니다. 결과는 차례로 **1.2974ms, 1.2972ms, 1.3059ms**였고 원본 min2phase는 **1.2949ms**였습니다. 학습량이 늘수록 더 빨라지는 흐름은 보이지 않았습니다. 세 설정 모두에서 실제 탐색 호출도 원본보다 평균 1.73~2.70% 많았습니다. [시작 방향 모델의 학습량별 비교](../benchmarks/dnn-scale/REPORT.md)

처음 15수를 10수로 줄였을 때 가장 눈에 들어온 건 줄어든 다섯 수였습니다. 실험을 마치고 보니 그 옆에 적어 둘 숫자가 하나 더 있었습니다. 같은 시간을 원래 솔버에 줬을 때 몇 수에 푸느냐는 것입니다. 제가 만든 모델이 이전보다 큐브를 더 많이 풀게 된 건 분명한 성과였습니다. 다만 이번 CPU 실험 결과를 보고, 실제 솔버의 기본 탐색에는 기존 min2phase 방식을 유지했습니다.
