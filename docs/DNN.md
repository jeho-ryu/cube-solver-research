# 큐브 DNN 실험: 후처리부터 시작 방향 선택까지

[전체 요약으로 돌아가기](../README.md)

신경망이 회전이나 탐색 순서를 선택하면 기존 min2phase보다 빠르게 풀거나, 같은 요청 예산에서 더 짧은 해를 찾을 수 있는지 실험했습니다. AlphaCube를 사용하는 실험과 직접 학습한 독립 모델 실험을 구분했습니다.

**자체 모델의 해결 수는 늘었지만, 이번 CPU 실험에서 min2phase를 꾸준히 앞서는 설정은 확인하지 못했습니다.** 성공하지 않은 결과도 대조군과 함께 남겼습니다.

## 1. DNN을 붙인 위치

| 위치 | 구현 | 목적 |
|---|---|---|
| 첫 해 이후 | AlphaCube 전체 재탐색·구간 교체 | 더 짧은 해법 |
| 회전 선택 | 자체 Policy·Policy+Value와 빔서치 | 독립적으로 큐브 해결 |
| Phase 1과 2 사이 | 후보를 모아 DNN 점수로 정렬 | 더 쉬운 Phase 2부터 탐색 |
| 탐색 시작 직전 | 작은 트리·DNN으로 시작 방향 선택 | 추론 호출을 줄이며 탐색 순서 개선 |

후보 정렬과 시작 방향 선택은 기존 탐색의 순서를 바꾸는 방법입니다. 독립 빔서치처럼 보관 한도 밖의 경로를 버리는 방식과 구분해야 합니다.

## 2. AlphaCube로 기존 해법 줄이기

### 구현

min2phase 첫 해를 보관한 뒤 두 가지 후처리를 적용했습니다.

1. **전체 재탐색:** 원래 입력에서 첫 해보다 짧은 깊이까지만 AlphaCube로 다시 풉니다.
2. **구간 교체:** 기존 해법의 구간 `W`보다 짧으면서 같은 변환을 만드는 수순 `Q`를 찾습니다.

구간 교체에서는 완성 상태에 `inverse(W)`를 적용한 상태를 풉니다. 그 상태를 `Q`로 완성했다면 `inverse(W) Q = identity`이므로 기존 구간을 `Q`로 대체할 수 있습니다. 교체 후에는 원래 큐브에 전체 수순을 적용해 다시 검증하고, 더 짧고 유효할 때만 채택합니다.

### 결과

10/20/25회 섞은 30개, AlphaCube small, CPU 4스레드, 빔 폭 1,024입니다. 첫 해 이후 각 후처리와 min2phase 추가 탐색에 요청 예산 3초를 주었습니다.

| 방식 | 평균 HTM | 첫 해보다 짧아진 큐브 | 총 절약 수 |
|---|---:|---:|---:|
| min2phase 첫 해 | 17.900 | — | — |
| AlphaCube 전체 재탐색 | 16.100 | 14/30 | 54 |
| AlphaCube 구간 교체 | 17.667 | 2/30 | 7 |
| min2phase 자체 추가 탐색 | **15.167** | **23/30** | **82** |

실제 사례에서는 첫 해 15수가 10수로 줄었습니다. 하지만 전체 평균에서는 자체 추가 탐색 대조군이 더 짧았습니다. 하이브리드가 모두 유효한 해를 반환한 데에는 기존 첫 해로 돌아가는 처리가 포함되므로 이를 AlphaCube 단독 성공률로 표시하지 않았습니다.

3초는 요청 예산이며 단계 사이에 시간을 확인합니다. 조기 종료하거나 마지막 작업 때문에 예산을 조금 넘길 수 있어 실제 실행 시간이 정확히 같지는 않습니다.

근거: [후처리 보고서](../benchmarks/dnn-postprocess/REPORT.md).

## 3. min2phase 풀이로 추가 학습

min2phase의 유효한 해법을 교사 데이터로 만들고, 기존 AlphaCube를 추가 학습한 모델과 같은 구조를 처음부터 학습한 모델을 비교했습니다.

| 지표 | 기존 AlphaCube | 추가 학습 | 처음부터 학습 |
|---|---:|---:|---:|
| 별도 테스트 상태 754개의 다음 행동 Top-1 | 64.59% | 66.31% | 25.86% |
| 새 큐브 60개 실제 해결 | 57/60 | 57/60 | 7/60 |

다음 회전을 맞히는 비율은 올랐지만, 완성까지 여러 단계를 이어 가는 해결 수는 늘지 않았습니다. 교사가 고른 한 회전과 일치하는지 측정한 값이므로 가능한 모든 좋은 회전을 평가한 정확도도 아닙니다.

근거: [교사 학습 보고서](../benchmarks/dnn-teacher/REPORT.md).

## 4. 독립 Policy+Value 솔버

AlphaCube를 사용하지 않는 자체 모델에서는 다음 회전 18개의 점수와 남은 시범 해법 길이를 함께 예측하게 했습니다. 정책 점수로 후보를 확장하고 Value 점수로 남길 경로를 정하는 빔서치입니다.

### 적용한 변경

- 학습 상태를 작은 데이터 47,061개에서 200,001개로 확대했습니다.
- 정책과 Value를 같은 모델에서 출력했습니다.
- 완성 상태로부터 반경 4 이내인 46,741개 상태의 정확한 접미 수순을 표에 저장했습니다.
- Top-6 → Top-9 → Top-18 재시도가 하나의 전체 시간 예산을 나누어 사용하도록 했습니다.

Value 정답은 유효한 시범 수순의 남은 길이입니다. 최단거리나 과대평가하지 않는 하한을 보장하지 않습니다.

### 같은 새 큐브 100개에서의 비교

빔 128, 최대 깊이 24, 전체 예산 0.5초로 각 큐브를 세 번 평가했습니다. 해결 큐브는 **세 번 모두 시간 내 성공한 입력**입니다.

| 방식 | 해결 큐브 | 성공 실행 |
|---|---:|---:|
| 이전 독립 정책 모델 | 26/100 | 78/300 |
| 작은 데이터 / 정책만 | 29/100 | 87/300 |
| 20만 데이터 / 정책만 | 35/100 | 105/300 |
| 20만 / Policy+Value | 43/100 | 129/300 |
| Policy+Value + 정답표 | 43/100 | 129/300 |
| 정답표 + 재시도 포함 전체 개선 | **47/100** | **141/300** |
| 같은 후보 수에서 Value 정렬만 제거 | 38/100 | 114/300 |
| min2phase 첫 해 | **100/100** | **300/300** |

데이터 확대·Value·재시도가 자체 모델의 해결 수를 늘렸습니다. 정답표만 추가했을 때 해결 수는 43개로 같았고, 이미 해결 가능한 입력의 마무리를 도왔습니다. 정답표의 효과 전체를 DNN의 효과로 보지 않았습니다.

20회 섞은 25개에서는 전체 개선 모델도 한 개도 해결하지 못했습니다. 섞은 회전 수는 실제 최단거리가 아니며, 이 표본은 전체 큐브 상태를 균등 추출한 것도 아닙니다. min2phase에는 같은 0.5초 벽시계 중단을 넣지 않았으므로 설정 차이도 유지해 표시합니다.

빔·Top-k·깊이·시간 제한이 경로를 버리므로 해결과 최단해를 보장하지 않습니다.

근거: [독립 솔버 v2 보고서](../benchmarks/dnn-standalone/REPORT.md).

## 5. Phase 2 후보를 DNN으로 정렬

거리표 사전 검사를 통과한 Phase 1 종료 후보를 최대 16개 모으고, `Phase 1에서 쓴 수 + 예측 Phase 2 길이`가 작은 후보부터 시도했습니다.

25회 섞은 새 큐브 60개를 세 번씩 평가했습니다.

| 21 HTM 이하 첫 해 탐색 | 중앙값 ms | 평균 ms | 성공 실행 |
|---|---:|---:|---:|
| 원본 min2phase | **0.5121** | **1.2986** | 180/180 |
| 후보를 모은 순서 | 0.7772 | 1.7637 | 180/180 |
| PDB 점수순 | 0.8536 | 1.8092 | 180/180 |
| DNN 점수순 | 0.8317 | 1.8601 | 180/180 |

후보 수집만으로도 지연이 늘었습니다. DNN으로 정렬한 뒤 탐색 호출이 줄어드는 부분이 있어도, 상태 복사·특징 계산·추론·정렬과 탐색 흐름 변경 비용을 상쇄하지 못했습니다.

검증 Phase 2 길이의 평균 절대 오차도 PDB+상수 보정이 0.8208, DNN이 0.8431이었습니다. 단순 기준과 비교해야 신경망의 추가 가치를 판단할 수 있었습니다.

근거: [후보 정렬 보고서](../benchmarks/dnn-ranking/REPORT.md).

### 고정 시간 품질과 메모리도 확인

같은 후보 정렬 모델을 새 100개에서 세 번씩 평가한 별도 실험입니다.

| 지표 | 기본 방식 | DNN 정렬 |
|---|---:|---:|
| 100ms 내 평균 해 길이 | 18.907 HTM | 19.040 HTM |
| 100ms 내 18 HTM 이하 반환 | 94/300회 | 70/300회 |
| 프로세스 피크 작업 집합 중앙값 | 66.08MiB | 72.76MiB |

메모리는 표·모델 준비를 포함한 프로세스 피크입니다. 증가분 전체를 가중치 크기로 해석하지 않았습니다. 품질과 메모리 개선이 확인되지 않아 이 모델을 근거로 거리표를 줄이는 후속 변경은 진행하지 않았습니다.

근거: [고정 시간 품질·메모리 보고서](../benchmarks/dnn-quality/REPORT.md).

## 6. 시작할 때 한 번만 DNN 사용

후보마다 추론하는 비용을 줄이기 위해 탐색 시작 전 여섯 방향 중 하나를 고르는 작은 모델을 시험했습니다. 최종 확대 실험은 거리표 최솟값이 같은 방향들 사이에서만 최대 한 번 추론했습니다.

모델은 `62 → 16 → 8 → 6`, FP32, 1,198개 파라미터, 가중치 파일 4,820바이트입니다. 구조는 유지하고 학습 큐브를 3천·1만·3만으로 늘렸습니다. 각 규모에서 초기값 세 개로 학습하고, 공통 검증 1,000개로 모델을 고정한 뒤 새 테스트 2,000개를 평가했습니다.

| 학습 큐브 | 평균 풀이 ms | 원본 대비 탐색 호출 |
|---|---:|---:|
| 원본 min2phase | 1.2949 | 1.0000배 |
| 3,000개 | 1.2974 | 1.0235배 |
| 10,000개 | 1.2972 | 1.0173배 |
| 30,000개 | 1.3059 | 1.0270배 |

DNN 행은 초기값 세 개의 평균입니다. 데이터가 늘면서 시간이나 탐색량이 지속적으로 줄어드는 흐름을 확인하지 못했습니다. 규모 간 주요 비교의 95% 구간에는 차이 없음이 포함됐습니다.

100 epoch를 고정했으므로 데이터가 커질수록 업데이트 횟수도 늘었습니다. 데이터 다양성만 분리한 실험은 아닙니다. 탐색 호출은 고유 방문 상태 수가 아닌 P1+P2 재귀 진입 수입니다.

근거: [학습량 확대 보고서](../benchmarks/dnn-scale/REPORT.md).

## 7. 실패에서 확인한 점

| 예상 | 실제 확인 | 이후 판단 |
|---|---|---|
| 다음 회전 예측이 좋아지면 더 많이 풀 것 | 정확도 상승에도 해결 수 57/60으로 동일 | 분류 지표와 실제 탐색 결과를 함께 평가 |
| 후보를 잘 정렬하면 바로 빨라질 것 | 수집·추론·정렬 비용으로 지연 증가 | 줄인 탐색 비용과 새로 든 비용을 함께 측정 |
| 작은 모델에 데이터를 더 주면 나아질 것 | 3천 → 3만에서 일관된 개선 없음 | 입력 특징·학습 목표를 별도로 검토 |
| 첫 해를 줄이면 기존 솔버보다 좋은 것 | min2phase 추가 탐색이 더 짧은 평균 해 | 추가 시간을 준 기준선과 비교 |
| 빔서치 실패는 짧은 해가 없다는 뜻 | 제한 때문에 경로가 버려질 수 있음 | 실패를 최단거리 증명으로 해석하지 않음 |

## 8. 검증 범위와 결론

출력은 외부 회전 엔진이나 별도 큐브 모델에서 재생했고, 학습·검증·테스트 분리와 저장된 집계를 확인했습니다. 다만 AlphaCube 사전학습 데이터의 전체 목록은 없으므로 해당 데이터와의 중복 여부는 확인하지 못했습니다. 실험별 입력·타이머 범위·정밀도와 예산이 달라 전체 수치를 하나의 속도 순위로 합칠 수 없습니다.

이번 연구의 결과는 DNN이 큐브를 개선할 수 없다는 일반적 결론이 아닙니다. **현재 CPU·모델·데이터·결합 방식에서는 추가 비용을 상쇄하는 꾸준한 우위를 얻지 못했다**는 결과입니다. 자체 모델을 개선한 성과와 기존 솔버를 이긴 성과를 구분하고, 이후에는 실제 탐색 비용을 더 잘 반영하는 입력과 학습 목표를 독립적으로 비교할 필요가 있습니다.
