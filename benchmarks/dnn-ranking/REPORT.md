## 실제로 바꾼 부분

기존 min2phase 원본 파일은 수정하지 않았습니다. 별도 Java 하위 클래스에서 `initPhase2Pre()` 진입 후보를 최대 16개 모읍니다. 후보를 수집하는 기존 Phase 1 PDB 탐색, 대칭과 pre-move 처리는 상속하며, Phase 2 내부 탐색과 PDB 가지치기도 원본 코드를 호출합니다.

후보 입력은 코너 8개·UD 엣지 8개·중간층 엣지 4개의 순열 원핫 144차원과 기존 PDB 값 3개입니다. Phase 2 진입 상태는 방향이 정리되어 있어 별도의 orientation 입력이 필요하지 않습니다. DNN은 PDB 하한에 더할 잔여 비용을 학습하고, `Phase 1 경로 길이(사전 회전 포함) + 예상 Phase 2 길이`로 정렬합니다. 예측값은 가지치기에 사용하지 않습니다.

DNN은 147→64→32→1, 파라미터 11,585개입니다. PyTorch로 학습한 FP32 가중치를 Java에서 직접 계산합니다. 후보 묶음을 한 번에 넘기되 내부 계산은 CPU의 단순 반복문입니다. GPU나 최적화된 배치 행렬 라이브러리는 사용하지 않았습니다.

최종 구현은 원본 경계 후보의 모든 마지막 회전·사전 회전 변형에 대해 PDB 검사를 먼저 수행합니다. 가능한 변형이 하나도 없으면 기존 반환 규칙으로 제외하고, 통과한 후보만 상태를 복사하고 점수화합니다. 대표 상태 한 개의 PDB 값만 보고 다른 변형까지 잘못 제거하지 않도록 원본 변형 검사 루프를 재사용했습니다.

후보 지연 처리 때문에 실제 Phase 2 탐색 실패 결과를 즉시 Phase 1의 축 건너뛰기에 반영하는 최적화는 보수적으로 적용하지 않습니다. 따라서 원본과의 차이를 순서 변경 하나만의 효과로 해석하면 안 됩니다. FIFO/PDB/DNN 세 방식은 같은 지연 처리와 사전 PDB 검사 구조를 사용하므로 DNN 정렬의 추가 효과는 이들 사이에서 비교합니다.

후보가 16개 모이면 처리하고, 현재 Phase 1 길이 탐색을 다 마친 경우에도 남은 후보를 처리합니다. 후보가 든 배치 안에서만 순서가 바뀌며 전체 후보를 전역 정렬하지 않습니다. 원본이 하나의 경계 후보에서 검사하는 마지막 회전·사전 회전 변형도 Phase 2 실행 시 유지합니다. DNN은 그 변형 모두가 아닌 대표 경계 상태의 거리를 예측한다는 제한이 있습니다.

## 데이터와 학습

시작 큐브는 학습 1200개, 검증 150개입니다. 각 입력에서 경계 후보 16개를 수집해 학습 19,082개, 검증 2,394개의 서로 다른 상태를 저장했습니다. 분할 간 후보 상태 중복은 제거했습니다.

라벨은 Phase 2의 제한된 10개 회전에서의 최단 거리입니다. PDB 하한부터 깊이를 증가시키며 Phase 2 탐색을 완전히 마친 경우만 확정 라벨로 저장했습니다. 이것은 18개 회전을 모두 허용하는 전체 큐브의 최단 거리가 아닙니다. 라벨 탐색 제한 10ms 안에 확정하지 못한 후보 7개는 제외했으며 어려운 예시가 덜 포함되는 편향이 있습니다.

학습 40 epoch 중 검증 MAE가 가장 작은 8번째 가중치를 선택했습니다. 학습 시간 2.80초, 검증 평균 절대 오차는 다음과 같습니다.

| 예측 방식 | 검증 MAE(회전 수) |
|---|---:|
| 기존 PDB 하한 | 3.0965 |
| PDB + 학습 데이터에서 구한 상수 3 | 0.8208 |
| DNN | 0.8431 |

**단순한 상수 보정이 DNN보다 예측 오차가 작았습니다.** 상수 보정은 PDB 후보 정렬 순서를 바꾸지 않습니다. 따라서 PDB 하한 대비 오차가 줄었다는 것만으로 DNN이 좋은 순서를 학습했다고 볼 수 없습니다.

| 검증 후보 선택 방식 | 선택 후보의 실제 총 길이 − 해당 묶음 최선 길이(평균) | 최선 후보 선택률 |
|---|---:|---:|
| 후보 수집 순서 | 1.633 | 17.3% |
| PDB 점수순 | 1.033 | 34.7% |
| DNN 점수순 | 1.093 | 35.3% |

이 값은 라벨이 남아 있는 검증 후보 안에서 대표 상태의 Phase 2 최단 거리로 계산한 보조 지표입니다. 실제 모든 변형을 포함한 솔버 실행 성능은 위 시간 실험으로 평가했습니다. 모델 선택이나 테스트 후 재학습에는 사용하지 않았습니다.

## 시간 측정·검증 범위

- 새 큐브 60개는 25회 회전으로 생성했습니다. 전체 큐브 상태에서 균등 추출한 대회용 표본은 아닙니다.
- 별도 입력 80개로 각 경로와 DNN을 예열했습니다. 초기 테이블 생성과 모델 로딩은 측정에서 제외합니다.
- Java 내부의 실제 경과 시간을 측정합니다. 후보 수집, 상태 복사, 특징 생성, DNN 계산, 정렬, 두 단계 탐색은 포함합니다. Python 통신, 입력 문자열에서 facelet 변환, 솔버 객체 생성, 사후 해법 검증은 제외합니다.
- 계측 솔버들은 호출 전체에 100ms를 허용합니다. 깊이 재귀 진입 256회마다 또는 후보 경계에서 시간을 확인하므로 초과할 수 있습니다.
- 원본 raw 기준은 계측 오버헤드를 보기 위한 별도 첫 해 측정입니다. 원본 `solution(...,21,1000000,0,0)` 그대로이며 100ms 벽시계 제한은 없습니다. 원본을 변형하지 않은 18회 제한 비교는 이 표에 포함하지 않았습니다.
- 18회 이하 실험은 처음부터 `maxDepth=18`로 요청합니다. 첫 해를 찾은 뒤 `next()`로 개선하는 방식과는 다릅니다.
- 같은 JVM의 단일 스레드로 실행하고, 입력과 반복마다 방식의 실행 순서를 회전시켰습니다. 전체 컴퓨터의 외부 부하는 통제하지 못하므로 작은 시간 차이는 과해석하지 않습니다.
- 저장된 1620개 실행 중 성공한 해법 1181개를 독립 Java 구현으로 다시 검증했습니다. 실패는 결과에서 제거하지 않았습니다. 데이터의 21,476개 Phase 2 해법도 모두 역수순으로 원래 상태를 재현하는지 검증했습니다.
- Java와 PyTorch의 예측값 100개 비교에서 최대 절대 오차는 0.00000142였습니다.

초기 `pilot` 실행에서 PDB로 제외될 후보까지 점수화하는 낭비를 발견해 사전 검사를 추가했습니다. 최종 `pdb-screened` 평가는 학습한 가중치·배치 크기·시간 제한을 그대로 고정하고 새 시드 909113의 큐브 60개로 수행했습니다. 초기 진단 결과는 `pilot/evaluation`에 별도로 보존했습니다.
