# C++ 대형 거리표와 Rob 비교 (2026-11-01)

거리표를 RAM 약 10.9GiB까지 확장했다. 같은 1스레드에서 기존 C++ ram 평균 0.2705ms → max 0.1163ms로 **57.0% 단축**됐다. 기존 ram·masks·max 단일 스레드는 2,000개 입력의 해법 수순까지 모두 일치했다.

C++ 단일 요청의 최저 평균은 **masks 4스레드 0.1021ms**, Rob 상주 풀 4스레드는 **0.0602ms**였다. 같은 1스레드에서는 max 0.1163ms, Rob 원본 0.1873ms, Rob 상주 풀 0.0836ms였다. max의 평균은 Rob 원본보다 37.9% 짧았지만 상주 풀보다 길었고, P95는 Rob 원본보다도 길었다. 평균과 꼬리 지연을 구분해 판단한다.

max의 RAM 증량은 masks 대비 단일 스레드 평균을 5.0% 줄였지만, 같은 4스레드 race에서는 22.1%, 8스레드 race에서는 31.9% 느렸다. 반면 **max 8스레드 배치는 초당 48,943개**로 기존 ram 8스레드보다 **2.67배**, masks 8스레드보다 **1.45배** 빨랐다. Rob 배치 처리량은 측정하지 않았다.

실용 설정은 단일 요청 평균 지연에 masks 4스레드 race, 대량 배치에 max 8스레드다. max 초기화는 1스레드 12.2초, 8스레드 5.8초였으며 위 풀이 시간에 포함되지 않는다. 원본 파일 검증과 원시 표 확장을 포함한 초기화이며, 파일 캐시는 따뜻한 조건이다.

측정 CPU: Intel Core Ultra 5 228V, 논리 CPU 8개, 물리 RAM 약 32GB. 첫 11개 설정 실험의 원자료는 ../max-holdout-20261101에 보존했다. 여기서는 max 4스레드를 추가해 새로운 입력으로 12개 설정을 비교했으며 실행 파일은 두 실험 사이에 바꾸지 않았다.

새 균등 무작위 합법 상태 2,000개 × 3라운드 × 2반복. 각 프로세스 300개 워밍업, 한 번에 한 솔버만 실행. 모든 설정은 출력 21 HTM 이하 해 하나를 찾는다. 최단해 보장은 없다.

기존 ram 실행 파일, Rob 원본/상주 풀은 수정 없이 사용했다. 새 masks는 Phase 1 이동 델타와 정확한 코너·UD 엣지 Phase 2 거리표를 추가한다. max는 같은 표를 원시 좌표로 펼쳐 RAM 약 10.9GiB에 상주시킨다. Rob 탐색 구현은 새 솔버에 링크하지 않았다.

큰 표는 시작 시 검증·확장하며 요청 입력이 도착한 뒤 탐색한다. 위 초기화는 파일 캐시가 따뜻한 조건이고 디스크 콜드 스타트 측정은 아니다. 대형 표는 작업자 간 공유하며 스레드별로 복제하지 않는다.

배치는 큐브 간 병렬 처리이며 race 단일 요청과 별도다. 배치 전체 6회 중앙값이며 입력 파일 읽기·IPC·JSON은 제외한다. Rob 배치 처리량은 측정하지 않았다.

요청 출력 144,000개와 배치 출력 96,000개를 포괄하는 8,477개 고유 입력·해법 쌍을 별도 54스티커 모델로 재생해 모두 완성 상태를 확인했다. 실패와 21 HTM 초과는 0건이다. masks/max 단일 스레드 수순은 전부 일치한다. Rob 원본/상주 풀의 단일 스레드 수순도 전부 일치한다.

protocol.json에 시드·실행 파일/표 해시·비교 조건, outputs.jsonl과 times.npz에 요청 원자료, batch_outputs.jsonl과 batches.json에 배치 원자료를 보존했다. startup.json에는 내부 초기화 및 외부 실행부터 ready까지 시간을 보존했다. 개발용 pilot 입력은 통계에 포함하지 않았다. 이 Windows PC와 표본에 한정한 결과이며 bootstrap은 모든 시스템 변동을 나타내지 않는다.
