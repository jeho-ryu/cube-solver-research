# DNN 후보 정렬: 고정 시간 해법 길이와 메모리 실험

**이번 고정 모델·후보 수집 방식에서는 해법 길이와 메모리 모두 개선되지 않았습니다.** 100ms에서 기본 방식 평균 18.907수,
DNN 19.040수였고, 18회 이하 해법은 각각 94/300회와 70/300회였습니다. 100ms의 동일 입력·반복 비교에서
DNN이 더 짧은 경우는 0회, 같은 경우는 262회, 더 긴 경우는 38회였습니다.

피크 작업 집합의 반복별 중앙값은 기본 66.08MiB, DNN 72.76MiB입니다. 추가 모델의 원시 데이터는 45.25KiB이고,
모든 방식의 정적 배열 데이터는 그대로였습니다. 피크 차이 전체를 모델 가중치 크기로 해석하면 안 됩니다.

예정한 1차 실험에서 이득이 확인되지 않아 이 모델을 근거로 가지치기 표를 축소하는 후속 변경은 진행하지 않았습니다.
이는 다른 모델·학습 목표·Phase 1 내부 탐색 유도의 가능성을 부정하는 결과는 아닙니다.

새 25회 스크램블 100개 × 3회 반복. 동일 큐브 반복은 독립 표본이 아닙니다.

## 메모리

각 반복마다 방식별 새 JVM을 사용했습니다. 아래 값은 반복별 측정의 중앙값입니다.

| 방식 | 피크 작업 집합(MiB) | 종료 전 작업 집합(MiB) | GC 후 Java 힙(MiB) | 정적 배열 데이터(KiB) | 모델 데이터(KiB) |
|---|---:|---:|---:|---:|---:|---:|
| stock | 66.08 | 53.56 | 2.87 | 989.92 | 0.00 |
| fifo | 73.28 | 54.36 | 2.88 | 989.92 | 0.00 |
| pdb | 71.51 | 55.39 | 2.89 | 989.92 | 0.00 |
| dnn | 72.76 | 54.32 | 2.95 | 989.92 | 45.25 |

작업 집합은 JVM·JIT 코드·테이블·객체 등을 포함합니다. 피크는 초기화와 예열도 포함한 프로세스 수명 중 최대값입니다. GC 후 힙은 요청 직후의 근사 관측이며 객체 크기의 정확한 합계가 아닙니다. 정적 배열/모델 데이터는 원시 원소의 바이트 합계로 배열 헤더·참조·정렬 패딩 및 객체 배열에 담긴 큐브 객체 내부 필드는 제외합니다. 학습 프로세스는 실행하지 않았고 Python 제어 프로세스는 솔버 메모리에서 제외했습니다.

## 해석과 제한

- DNN은 표를 대체하지 않으며 모든 방식이 동일한 표를 보유합니다. 따라서 더 짧은 해법을 찾더라도 표 메모리는 줄지 않습니다.
- 모델은 Phase 2 진입 후보의 대표 상태를 평가합니다. Phase 1 내부의 매 회전을 예측하는 모델과는 다릅니다.
- 모든 방식에 공통으로 21회 이하 해법부터 구한 뒤, 찾은 길이−1을 한도로 처음부터 재탐색하는 anytime 래퍼를 사용했습니다. 원본의 next() 재개 방식과 동일하지 않으므로 원본의 최고 성능을 대표하지 않습니다.
- 100ms의 연속 탐색 중 해법이 반환된 시간을 기록해 10/50/100ms 결과를 읽습니다. 해법 반환 시간이 기준을 넘으면 해당 시점의 성공으로 세지 않습니다. 실제 중단은 시간 확인 간격 때문에 초과할 수 있습니다.
- Java 탐색 객체 생성, 상태 검증, 탐색 재시작, 후보 복사와 정렬, DNN 추론은 시간에 포함합니다. 테이블 초기화·가중치 로딩·예열·Python IPC·독립 해법 검증은 제외합니다.
- 후보 수집으로 기존 Phase 2 피드백이 지연됩니다. DNN 자체의 효과는 같은 수집 구조인 FIFO/PDB 대조군과도 비교해야 합니다.
- 방식 실행 순서를 섞고 각 방식은 독립 JVM을 사용했습니다. 운영체제 스케줄링·JIT·외부 부하는 완전히 통제하지 못했습니다.
- 스크램블은 같은 면 연속 회전을 제외한 25회 회전으로 생성했습니다. 전체 합법 상태의 균등 표본은 아닙니다. 기존 학습·검증·이전 테스트의 시작 상태와 중복을 제외했으며, 본 실험의 예열 상태도 테스트와 분리했습니다.
- 저장된 개선 해법 2738개 전부를 별도 54면 facelet 구현으로 재생해 검증했습니다.

측정 원본: `results.jsonl`, `memory.json`, `cases.json`, `summary.json`, `metadata.json`, `audit.json`. 재실행 명령과 코드 설명은 상위 README.md에 있습니다.

## 저장 결과 재검증

`independent_audit.json`에서 1,200회 실행의 누락·중복, 모든 개선 해법의 독립 재생, 원본 집계 재계산,
모델·소스 해시 일치를 확인했습니다. 테스트 스크립트의 실제 큐브·시간 제한·메모리 검증도 통과했습니다.

100개 큐브 각각의 3회 평균 차이를 계산하고 큐브 단위로 5,000회 재표집한 결과,
100ms의 DNN−기본 해법 길이 차이는 +0.133수, 부트스트랩 95% 구간은 [+0.077, +0.193]수였습니다.
이 구간은 이번 입력 표본의 변동을 나타내며 다른 장비·모델에 대한 보장은 아닙니다.
