# 독립 솔버 v2: 학습 확대·Value·정답표·재탐색

새 큐브 100개를 각 방식으로 3회 풀이했습니다. **이전 방식 26/100개 → 전체 개선 47/100개 해결**입니다. 여기서 해결 큐브는 모든 반복에서 제한 시간 내 성공한 입력입니다.
**min2phase는 100/100개를 해결했습니다. 전체 개선이 원본보다 전반적으로 빠르다는 결과는 아닙니다.** 학습과 탐색 안내는 나아졌지만 어려운 입력의 해결률과 처리 시간에 한계가 남았습니다.

## 같은 입력에서 측정한 전체 결과

| 방식 | 해결 큐브 | 성공 실행 | 평균 시간(ms) | 중앙값(ms) | 성공 평균 HTM |
|---|---:|---:|---:|---:|---:|
| min2phase 첫 해 | 100/100 | 300/300 | 0.418 | 0.251 | 14.52 |
| 이전 독립 정책 모델 | 26/100 | 78/300 | 23.325 | 28.591 | 5.42 |
| 작은 데이터 / 정책만 | 29/100 | 87/300 | 29.041 | 36.208 | 6.14 |
| 20만 데이터 / 정책만 | 35/100 | 105/300 | 27.553 | 35.849 | 6.77 |
| 20만 / Policy+Value | 43/100 | 129/300 | 36.845 | 50.707 | 8.37 |
| Policy+Value + 정답표 | 43/100 | 129/300 | 35.304 | 53.374 | 8.33 |
| 전체 개선: 정답표 + 재시도 | 47/100 | 141/300 | 100.724 | 168.902 | 9.30 |
| 동일 후보 수 / Value 정렬 제거 | 38/100 | 114/300 | 96.231 | 146.430 | 6.84 |

시간은 실패를 포함한 모든 실행의 관측값입니다. 실패를 빨리 반환한 것을 풀이 속도 향상으로 해석하지 않습니다. 성공한 입력 집합이 다르므로 성공 평균 길이만으로 해법 품질을 비교하지 않습니다.
모든 독립 솔버는 빔 128, 최대 깊이 24, 전체 예산 0.5초입니다. min2phase는 최대 길이 21의 첫 해이며 별도 벽시계 중단을 넣지 않았습니다. 현재 결과에서 독립 솔버의 실패는 대부분 깊이 제한 때문이며, 예산을 다 쓰지 않고 끝날 수 있습니다.
CPU FP32·4스레드 환경이며, 알고리즘 순서를 입력별·반복별로 회전시켰습니다. 모델/PDB 초기화와 예열은 측정 전에 수행했습니다. 신경망 추론, 후보 생성, 상태 전이, 목표·표 조회, 정렬, 재시도는 풀이 시간에 포함됩니다. 모델·표 로딩, 데이터 생성·학습, 입력 변환, 독립 해법 검증은 제외합니다. min2phase 타이머에는 내부 스크램블 변환이 포함됩니다.

## 어떤 변경이 기여했는가

1. **데이터 확대:** 같은 Policy+Value 구조에서 정책만 사용한 비교는 29개 → 35개 해결입니다. 작은 데이터는 큰 데이터의 정확한 부분집합이며, 기존 라벨을 바꾸지 않았습니다.
2. **Value 안내:** 후보 묶음·표·재시도를 맞춘 비교에서 Value 없이 38개, Value 정렬을 사용하면 47개를 해결했습니다. 정책만 쓰는 기본 방식과 Value 방식 사이에는 후보 묶음 크기도 달라지므로 이 비교를 우선 해석합니다.
3. **정답표:** 재시도 전 해결 수는 43개 → 43개입니다. 해결 수 증가와 이미 해결 가능한 큐브의 마무리 시간 단축을 구분합니다.
4. **재시도:** Value+표의 43개에서 47개로 늘었습니다. 추가 시도는 실패한 입력에서도 시간을 쓰므로 전체 평균 시간은 증가할 수 있습니다.

| 앞 방식 → 뒤 방식 | 공통 성공 큐브 | 뒤 방식이 빠른 큐브 | 앞/뒤 시간비 중앙값 | 뒤 방식 HTM 변화 |
|---|---:|---:|---:|---:|
| 작은 데이터 / 정책만 → 20만 데이터 / 정책만 | 27 | 11 | 0.991 | -0.48 |
| 20만 데이터 / 정책만 → 20만 / Policy+Value | 35 | 4 | 0.764 | -0.26 |
| 20만 / Policy+Value → Policy+Value + 정답표 | 43 | 43 | 12.520 | -0.05 |
| Policy+Value + 정답표 → 전체 개선: 정답표 + 재시도 | 43 | 34 | 1.119 | +0.00 |
| 동일 후보 수 / Value 정렬 제거 → 전체 개선: 정답표 + 재시도 | 38 | 19 | 1.001 | +0.29 |
| 이전 독립 정책 모델 → 전체 개선: 정답표 + 재시도 | 26 | 25 | 11.933 | +0.54 |
| min2phase 첫 해 → 전체 개선: 정답표 + 재시도 | 47 | 1 | 0.125 | +0.51 |

공통 성공은 두 방식 모두 모든 반복에서 시간 내 성공한 큐브입니다. 시간비가 1보다 크면 뒤 방식이 빠릅니다. 이 표는 해당 공통 입력에만 적용되며, 어려운 실패 입력까지 포함한 전체 속도 우위를 뜻하지 않습니다.

## 실제 신경망·정답표 사용

| 방식 | DNN 호출 실행 | 시작 상태에서 표만으로 해결 | 표 접미사로 해결 | 재시도로 해결 | 평균 추론(ms) | 평균 목표·표 검사(ms) |
|---|---:|---:|---:|---:|---:|---:|
| 이전 독립 정책 모델 | 300 | 0 | 0 | 0 | 10.125 | 0.000 |
| 작은 데이터 / 정책만 | 300 | 0 | 0 | 0 | 10.998 | 4.972 |
| 20만 데이터 / 정책만 | 300 | 0 | 0 | 0 | 10.467 | 4.717 |
| 20만 / Policy+Value | 300 | 0 | 0 | 0 | 15.014 | 8.582 |
| Policy+Value + 정답표 | 297 | 3 | 129 | 0 | 13.644 | 9.580 |
| 전체 개선: 정답표 + 재시도 | 297 | 3 | 141 | 12 | 38.274 | 26.667 |
| 동일 후보 수 / Value 정렬 제거 | 297 | 3 | 114 | 6 | 28.695 | 29.279 |

시작 상태가 표에 있으면 DNN을 호출하지 않고 해결합니다. 이 속도는 정답표의 효과입니다. 원시 `table_seconds`에는 표를 끈 경우에도 수행하는 목표 상태 검사 시간이 포함됩니다. 이전 정책 모델은 그 검사 시간을 별도로 계측하지 않았으므로 0이 기록됩니다.
표는 완성 상태에서 모든 18개 회전으로 반경 4까지 BFS하여 만듭니다. 반경별 상태 수는 1, 18, 243, 3,240, 43,239개입니다. 표의 전체 접미 수순을 적용해 검증했고, 길이 제한을 넘는 해법을 반환하지 않습니다.
표 파일 787,683바이트, 딕셔너리 메모리 추정 8,413,628바이트, 생성·저장 1.102초, 이번 실행의 로딩 0.085초입니다. 이 준비 비용은 풀이 시간에서 제외했습니다.

## 학습 결과

| 모델 | 학습 상태 | 선택 epoch | 학습 시간 | 검증 Top-6 | 남은 시범 길이 MAE |
|---|---:|---:|---:|---:|---:|
| small | 47,061 | 8/30 | 30.21초 | 68.38% | 2.141 |
| large | 200,001 | 9/30 | 118.25초 | 74.35% | 2.087 |

두 모델은 모두 153,875개 파라미터이며 같은 난수 시드에서 무작위 초기화했습니다. 출력은 다음 회전 18개와 Value 1개입니다. 데이터 생성에는 37.06초가 걸렸습니다.
새 시작 상태 15,644개 중 3,911개는 기존 정책으로 몇 단계 이동한 상태입니다. 반드시 실제 빔 탐색 실패 상태만 모은 데이터는 아닙니다.
Value 정답은 유효한 시범 수순의 남은 길이입니다. 최단거리나 과대평가하지 않는 휴리스틱으로 보장되지 않습니다. 정책 Top-k는 선생이 선택한 한 회전의 포함률이며 전체 경로 생존율이나 최적 회전 정확도가 아닙니다.
검증 목적함수는 정책 교차 엔트로피 + 4 × (길이 오차/20)의 평균 제곱입니다. 검증으로 epoch를 고르고, 다른 설정 선택 큐브 20개에서 점수 비중을 골랐습니다. 최종 큐브 100개 결과로 설정이나 모델을 다시 고르지 않았습니다.
선택된 정렬 점수는 `예측 남은 길이 + 0.05 × 누적 음의 로그확률`입니다. 같은 깊이에서 후보를 비교하므로 공통인 현재 깊이를 더해도 순서는 바뀌지 않습니다.
정책으로 최대 2B개를 고른 뒤 상태를 생성·조회하고, Value로 B개를 남깁니다. 살아남은 상태의 정책 출력을 다음 단계에서 재사용합니다. Value 비교군은 동일한 2B개를 표에서 확인한 후 정책 순서로 B개를 남깁니다.
재시도는 Top-6, Top-9, Top-18의 별도 빔서치입니다. 누적 마감은 전체 예산의 25%, 55%, 100%이며 일찍 끝난 시도의 미사용 시간은 뒤 시도가 쓸 수 있습니다. 모든 노드를 보관하는 best-first 탐색은 아니며, 학습된 값만으로 가지를 영구 제거하지 않아도 빔·Top-k·깊이·시간 제한 때문에 해결을 보장하지 않습니다.

## 검증 및 파일

최종 기록 2,400행, 성공 해법 1,083개를 독립 Java 검증기와 자체 큐브로 확인했습니다. 모든 집계를 다시 계산하고 모델·표·입력·코드·결과 해시를 확인했습니다.
학습 데이터 200,001행을 저장된 시범 경로로 재구성했고, 학습/검증 중복과 이전 테스트 상태의 보호를 확인했습니다. 기존 독립 큐브 환경의 18회전 및 무작위 상태 검증을 재사용하고, 이번 변경의 정답표·역회전·Value 순서·재시도 예산 테스트 4개를 통과했습니다.
