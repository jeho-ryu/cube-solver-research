# C++ max 느린 입력 최적화 결과 (2026-11-02)

같은 1스레드·max 메모리 조건에서 기존 실행 파일과 새 실행 파일을 재측정했다. **P95는 66.6%, P99는 52.8%, 평균은 56.4% 줄었다.** 1ms를 넘긴 입력은 2,000개 중 84개에서 15개로 감소했다.

|---|---:|---:|---:|
| 평균 | 0.2363ms | 0.1030ms | 56.4% |
| 중앙값 | 0.1311ms | 0.0541ms | 58.7% |
| P95 | 0.8867ms | 0.2961ms | 66.6% |
| P99 | 1.7550ms | 0.8280ms | 52.8% |
| 관측 최대 | 5.0509ms | 3.6690ms | 27.4% |

| 1ms 초과 입력 | 84개 | 15개 | |
| 평균 출력 길이 | 20.542 HTM | 20.630 HTM | |

2,000개 중 1,753개에서 새 방식이 더 빨랐다. 모든 입력에서 빨라진 것은 아니다. 기존에는 1ms 이하였으나 새 방식에서는 1ms를 넘긴 입력이 10개 있고, 두 방식 모두 1ms를 넘긴 입력이 5개다. 관측 최대는 이 표본의 값이며 최악 실행 시간 보장이 아니다. 출력은 모두 21 HTM 이하이며 평균 출력 길이는 0.088수 늘었다.

## 구현

추가 pre-move 없이 Phase 1 깊이별·여섯 방향별로 탐색을 시도한다. 각 시도는 Phase 1과 Phase 2 재귀 진입을 합쳐 512노드까지 진행한다. 한도를 넘기면 해당 시도를 빠져나와 다음 방향으로 넘어간다. 해가 없으면 2,048노드 예산으로 한 차례 더 시도한 뒤 기존 pre-move 포함 탐색으로 돌아간다.

시간 대신 노드 수를 기준으로 전환하므로 실행마다 결과가 일정하며 매 노드의 시계 호출 비용이 없다. 큰 거리표는 기존과 동일하고 공유 조회표 약 10.9GiB를 사용한다. 1스레드 요청은 호출 스레드에서 직접 실행한다. 단일 요청 race의 방향별 병렬 탐색은 기존 경로를 사용한다. 큐브 간 batch의 각 큐브에는 새 serial 탐색이 적용된다.

예산은 각 선행 시도만 제한하며 전체 요청을 강제로 시간 초과시키지 않는다. 어렵게 남은 입력은 기존 탐색으로 처리한다. 최단해나 일정 시간 이내 종료를 보장하지 않는다.

## 측정과 검증

개발 입력과 겹치지 않는 새 합법 무작위 상태 2,000개를 사용했다. 시드는 261102113이다. 각 실행 파일을 300개 입력으로 워밍업한 뒤 3라운드 × 2반복 측정했다. 한 번에 한 솔버만 실행하고 라운드별로 설정 실행 순서를 바꿨으며, 각 설정에는 동일한 무작위 입력 순서를 사용했다.

시간은 입력별 반복 중앙값 → 라운드 중앙값으로 요약한 뒤 평균 및 분위수를 계산했다. 초기화·IPC·출력·독립 재생 검증은 제외하고 C++ 내부 `solve_ns`를 사용했다. 앞선 날짜/실험의 절대 시간과 섞지 않았다. 이번 기존 max의 라운드 평균은 0.2403/0.2370/0.2253ms, 새 방식은 0.1042/0.1038/0.1040ms였다.

입력 단위 paired bootstrap 95% 구간에서 새 방식/기존 방식의 시간비는 평균 0.401–0.475, P95 0.284–0.410, P99 0.376–0.691이다. 이 구간은 표본 큐브에 대한 것이며 모든 OS·전력·온도 변동을 포함하지 않는다.

최종 측정 출력 24,000개를 포괄하는 고유 입력·해법 쌍을 별도 54스티커 모델에서 재생했다. 모두 완성 상태이며 실패·21수 초과는 없었다. 각 바이너리의 serial 해법은 모든 반복에서 동일했다. native·portable의 추가 정확성 검사 2,496개, 잘못된/불가능 입력 처리, max/masks 및 다중 스레드 batch 간 serial 수순 일치도 통과했다. 표 데이터와 로더는 변경하지 않았다.

두 개발 후보 중 512→2,048노드를 채택했다. 더 이른 전환인 128→512→2,048노드는 개발 표본의 P99가 나빠져 채택하지 않았다. 개발 표본은 최종 통계에 포함하지 않았다.
